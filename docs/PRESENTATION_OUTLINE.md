# Kuchbrtna — план презентации и видео

Цифры ниже — финальный замер v11 (`harness/run_task.py --repeats 2`, Kaggle T4). Если финальный
прогон даст другие числа, брать их из README.md (раздел «Результаты и ограничения»).

## Слайды (8–10)

1. **Проблема.** Дообучение Qwen2.5-1.5B (4-бит, LoRA) на бесплатной Kaggle T4: Soup идёт ~80–90 с и
   занимает 14,3 ГБ из 15. Цель — быстрее и легче, с тем же адаптером того же качества.
2. **Где время и память (профиль базы).** 36 % — матричные умножения, 44 % — мелкие поэлементные операции
   и приведения типов, 7 % — softmax по словарю 152k, логиты [4×512×152k] занимают гигабайты.
3. **Главный кернел — fused lm_head + cross-entropy** (`fused_ce.py`). Логиты считаются кусками по
   256 строк; один Triton-кернел за одно чтение даёт loss, энтропию, argmax и сразу градиент; полные
   логиты никогда не существуют. Микробенчмарк: **1,83× быстрее, 5,8 ГБ → 0,6 ГБ**.
4. **Остальные кернелы.** NF4-распаковка в один запуск (бит в бит с bitsandbytes), RMSNorm и
   add+RMSNorm, RoPE (бит в бит с transformers). Таблица микробенчмарков: RMSNorm 3,1×, RoPE 2,6×,
   NF4 1,5×.
5. **Удаление паддинга.** ~43 % позиций батча — паддинг. Слои считают только реальные токены,
   attention — по каждой строке на её длине; dropout LoRA с теми же масками, что у базы.
6. **Offload активаций.** Самые большие тензоры для backward (gate/up MLP, ~1 МБ на токен) уходят в
   pinned-память хоста по второму CUDA-потоку и возвращаются на слой раньше — параллельно со счётом.
7. **Мелочи, которые дали секунды.** Компиляция Triton в фоне во время загрузки модели; эмбеддинг в fp16
   (−0,9 ГБ, те же значения); подготовка датасета Soup без лишнего хеширования (−2 с).
8. **Результаты (v10, --repeats 2):**

   | | База | Решение | |
   |---|---:|---:|---:|
   | Полное время | 78,4 с | 54,5 с | **1,44×** |
   | Пик памяти | 14 345 MiB | 3 197 MiB | **4,49×** |
   | Eval loss | 2,04964 | 2,04965 | +0,000 % |

   Все 10 проверок PASS, наши кернелы — 12,5 % времени обучения, 48 тестов кернелов + 79 тестов Soup.
   Шаг обучения: 0,43 с против 0,87–0,91 с у базы (~2,1×).
9. **Путь по версиям** (график из таблицы в README): v1 1,1× / 1,7× → v6 1,3× / 2,6× → v8 1,6× / 3,2× →
   v11 1,44× / 4,49× (наше время 54,5 с — лучшее; отношение зависит от скорости базы в сессии). Каждая версия проверялась полным прогоном и сохранена отдельной веткой.
10. **Ограничения и дальше.** Матричные умножения cuBLAS и attention не заменяли — шаг упирается в них;
    время на Kaggle плавает между сессиями (база 76–93 с). Дальше: int8-умножения, offload весов по слоям,
    уменьшение синхронизаций CPU/GPU.
